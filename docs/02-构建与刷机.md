# 02 构建与刷机

## 1. 环境准备

建议在 Ubuntu 22.04/24.04 或 Debian 12/13 的 x86_64 主机上构建。

```bash
sudo apt update
sudo apt install -y build-essential git curl xz-utils cmake \
  bison flex libssl-dev libncurses-dev bc device-tree-compiler \
  gcc-aarch64-linux-gnu g++-aarch64-linux-gnu \
  libusb-1.0-0-dev libudev-dev dh-autoreconf \
  swig python3-dev python3-setuptools python3-pyelftools libgnutls28-dev
```

> 后 5 个包是 U-Boot v2026.01 的 binman / dtc Python 绑定 / mkeficapsule 编译所必需，缺一会在 `make uboot` 阶段报 `setuptools`、`swig`、`elftools`、`gnutls/gnutls.h` 相关错误。基础镜像若走 BT 下载，另需 `apt install aria2`。

资源需求：

- 磁盘：源码 + 编译中间产物 + 基础镜像 + 最终镜像，建议预留 **25 GB** 以上。
- 内存：内核并行编译建议使用 `-j$(nproc)`；内存小于 4GB 时可手动降低并行度。
- 网络：需要访问 GitHub、Armbian 镜像站和 USTC 镜像。

### 1.1 国内 GitHub 下载加速（默认已启用）

本项目不使用 `git clone`（在国内网络下常卡死），改为从 `codeload.github.com` 下载固定 commit 的 tarball，并统一经过 `gh-proxy.com` 代理。实测速度约 **1.5 MB/s**，而直连仅约 **24 KB/s**。

相关配置在 `config/project.env`：

```bash
USE_GH_PROXY=1
GH_PROXY=https://gh-proxy.com
```

- 代理同时作用于 `raw.githubusercontent.com`（AP6255 固件、ALSA UCM），对 Armbian/USTC 镜像地址不生效。
- 若代理不可用，可换其他代理前缀，或设 `USE_GH_PROXY=0` 走直连。
- tarball 缓存在 `sources/.tarballs/`，重复执行 `make fetch` 不会重新下载；源码解压到 `sources/<name>`，以 `.tn3399-fetched` 记录 commit。
- 因为 tarball 不含 `.git`，U-Boot 补丁改用 `patch -p1` 应用，效果与 `git apply` 相同。

### 1.2 Armbian 基础镜像的国内下载（BT 实测最快）

Armbian 基础镜像（约 340 MiB）的国内镜像站（USTC、南科大）对直连下载启用了 Anubis 反机器人验证，curl 会拿到验证页而非镜像；官方 `dl.armbian.com` 直连又很慢（实测约 25 KB/s）。**已验证最快的方式是用官方 `.torrent` 走 BT**：

```bash
# 1. torrent 与 .sha 文件不受 Anubis 拦截，可直接下载
IMG="Armbian_26.8.1_Nanopim4v2_trixie_current_6.18.44_minimal.img.xz"
BASE="https://mirrors.ustc.edu.cn/armbian-dl/nanopim4v2/archive"
UA="Mozilla/5.0 (X11; Linux x86_64)"
curl -sSL -A "$UA" -o /tmp/base.torrent "$BASE/${IMG}.torrent"

# 2. aria2 BT 下载（实测约 4.9 MB/s，1 分钟内完成）
mkdir -p sources/base
aria2c --continue=true --max-tries=0 --seed-time=0 \
       --dir=sources/base --out="$IMG" /tmp/base.torrent

# 3. 校验（期望哈希见 config/project.env 的 ARMBIAN_BASE_SHA）
sha256sum "sources/base/${IMG}"
```

下载完成后再执行 `make fetch`，脚本检测到文件哈希一致会直接跳过镜像下载，仅补齐源码与固件。若 BT 不可用，可退回 `fetch_file` 的断点续传（`curl -C -`），但官方源很慢，需耐心等待。

## 3. 刷机

### 3.0 烧录工具准备（含可靠下载链路）

本项目最终镜像是**裸扇区镜像**（包含 32 KiB 偏移处的 U-Boot），不是 Rockchip `update.img`。因此：

- **SD 卡**：用系统自带 `dd` 整盘写入即可，无需 Rockchip 专有工具。
- **eMMC / MaskRom / Loader**：推荐 Linux 下的 `rkdeveloptool`；`upgrade_tool` 作为功能更全的可选替代（闭源）。
- **Windows 图形界面**：可选 `RKDevTool` + `DriverAssistant`，但本项目不依赖它，优先使用随固件包提供的同版工具。
- **串口调试**：`miniterm`（PySerial）或 `minicom`，波特率固定 **1500000**。

#### 3.0.1 Linux USB 烧录工具（推荐）

两种获取方式任选其一：

**方式 A：直接使用 rkbin 固定版本的预编译二进制（最快、可校验）**

本项目锁定 rkbin commit `3e288fe814e059dd06833495f845cab04ac20a5c`，对应工具已实测可下载：

```bash
RKBIN_COMMIT=3e288fe814e059dd06833495f845cab04ac20a5c
mkdir -p tools && cd tools

curl -fL -o rkdeveloptool \
  "https://gh-proxy.com/https://raw.githubusercontent.com/rockchip-linux/rkbin/${RKBIN_COMMIT}/tools/rkdeveloptool"
curl -fL -o upgrade_tool \
  "https://gh-proxy.com/https://raw.githubusercontent.com/rockchip-linux/rkbin/${RKBIN_COMMIT}/tools/upgrade_tool"

chmod +x rkdeveloptool upgrade_tool
sha256sum rkdeveloptool upgrade_tool
```

预期 SHA256（与上述 commit 一一对应）：

| 工具 | SHA256 | 类型 |
|---|---|---|
| `rkdeveloptool` | `6d684c8ac957369dbe8c75a1e2a0815e1b25eca654c5cc4e9dd1d6ba4133b74d` | x86-64 ELF，动态链接 |
| `upgrade_tool` | `6748945290d63d119b542b9e123a0896510e98e8b0a6f4ac279c8a527da62102` | x86-64 ELF，静态链接 |

`rkdeveloptool` 运行时需要 `libusb-1.0-0` 与 `libudev1`：

```bash
sudo apt install -y libusb-1.0-0 libudev1
sudo install -m 0755 rkdeveloptool upgrade_tool /usr/local/sbin/
rkdeveloptool -V || true
```

> 上述地址走 `gh-proxy.com` 国内加速；直连源为 <https://raw.githubusercontent.com/rockchip-linux/rkbin/master/tools/>。目录索引见 <https://github.com/rockchip-linux/rkbin/tree/master/tools>。

**方式 B：从 Rockchip 官方源码编译 rkdeveloptool**

- 源码仓库：<https://github.com/rockchip-linux/rkdeveloptool>
- 官方说明：<https://opensource.rock-chips.com/wiki_Rkdeveloptool>
- 国内加速 tarball：<https://gh-proxy.com/https://codeload.github.com/rockchip-linux/rkdeveloptool/tar.gz/refs/heads/master>

```bash
sudo apt install -y build-essential autoconf automake libtool pkg-config \
                    libudev-dev libusb-1.0-0-dev

curl -fL -o rkdeveloptool.tar.gz \
  "https://gh-proxy.com/https://codeload.github.com/rockchip-linux/rkdeveloptool/tar.gz/refs/heads/master"
tar xzf rkdeveloptool.tar.gz
cd rkdeveloptool-*
autoreconf -i
./configure
make -j"$(nproc)"
sudo install -m 0755 rkdeveloptool /usr/local/sbin/
```

若 `./configure` 报 `PKG_CHECK_MODULES` 找不到 `libusb-1.0`，补装 `pkg-config libusb-1.0-0-dev` 后重试。

**Linux USB 权限（两种方式都需要）**

```bash
echo 'SUBSYSTEM=="usb", ATTR{idVendor}=="2207", MODE="0666"' | \
  sudo tee /etc/udev/rules.d/99-rockchip.rules
sudo udevadm control --reload-rules && sudo udevadm trigger
```

- 国内加速直链：<https://gh-proxy.com/https://raw.githubusercontent.com/retro98boy/tiannuo-tn3399-v3-linux/main/tools/rk3399_loader_v1.30.130.bin>
- SHA256：`15e4c1e74fba085e8e881ca3c2db77076a4adc620ed848fdf5608e327b8a1587`

必须与本项目 U-Boot 的 800MHz DDR blob（`rk3399_ddr_800MHz_v1.30.bin`）配套；换 DDR blob 时也要换对应 loader。

#### 3.0.3 Windows 图形工具（可选）

- 安装说明（含官方直链）：<https://docs.radxa.com/som/nx/nx4/getting-started/install-system/emmc-system/install-rkdevtool>
- 驱动 `DriverAssistant v5.14`：<https://dl.radxa.com/tools/windows/DriverAssitant_v5.14.zip>
- `RKDevTool v2.96-20221121`：<https://dl.radxa.com/tools/windows/RKDevTool_Release_v2.96-20221121.rar>

> 这两条直链来自 Radxa 官方文档页；国内网络若打不开 `dl.radxa.com`，以文档页中更新的链接为准。安装驱动时先点“卸载驱动”再点“安装驱动”，否则旧驱动可能导致设备识别不到。RK3399 用 v2.84–v2.9x 均可，优先使用固件发布方随包提供的版本。

#### 3.0.4 SD 卡与串口工具

| 用途 | 工具 | 获取方式 |
|---|---|---|
| SD 卡整盘写入 | `dd`（GNU coreutils，系统自带） | 无需额外下载；用法见 3.1 |
| 串口控制台 | `miniterm`（PySerial） | PyPI：<https://pypi.org/project/pyserial/>；或 `sudo apt install python3-serial` |
| 串口控制台（替代） | `minicom` / `screen` | 系统包管理器安装即可 |

```bash
sudo apt install -y python3-serial          # Debian/Ubuntu
python3 -m pip install --user pyserial      # 或 PyPI 安装
miniterm /dev/ttyUSB0 1500000               # 本板固定 1500000 8N1
```

串口模块建议 **CP2104**；CH340G / PL2303HX 在本板上常见只能读不能写。

### 3.1 SD 卡

```bash
sudo dd if=output/Armbian_TN3399_V3_vendor6.1_*.img of=/dev/sdX \
  bs=4M oflag=sync status=progress
sync
```

`/dev/sdX` 请通过 `lsblk` 确认，不要写错设备。

### 3.2 eMMC（MaskRom / Loader 模式）

工具安装、下载链与 udev 权限见 3.0；以下命令假设 `rkdeveloptool` / `upgrade_tool` 已在 `PATH` 中。

需要 USB OTG/Micro-USB 线。长按 RECOVER 再上电，或先从串口进入 U-Boot 执行：

```text
mmc dev 0
mmc erase 0 2000
reset
```

然后：

```bash
# 查看设备：应出现 Vid=0x2207,Pid=0x330c
rkdeveloptool ld

# 下载 DDR 初始化 loader（本项目已下载到 firmware/）
rkdeveloptool db firmware/rk3399_loader_v1.30.130.bin

# 整盘写入镜像
rkdeveloptool wl 0x0 output/Armbian_TN3399_V3_vendor6.1_*.img

# 重启
rkdeveloptool rd 3
```

也可用 Rockchip `upgrade_tool`：

```bash
upgrade_tool db firmware/rk3399_loader_v1.30.130.bin
upgrade_tool wl 0x0 output/Armbian_TN3399_V3_vendor6.1_*.img
```

> 本板 DDR3 为三星 K4B8G16，`config/project.env` 中 `DDR_BLOB` 已默认设置为 rkbin 自带的 `bin/rk33/rk3399_ddr_800MHz_v1.30.bin`（用户确认 800MHz 系列可用；旧版 v1.24 已从新版 rkbin 移除，仅作历史备份）。若 MaskRom 无法进入或 loader 初始化 DRAM 失败，请检查 USB 线、供电和按键时序；若仍失败，可尝试 rkbin 中其他 800MHz DDR blob，改 `DDR_BLOB` 后重新 `make uboot`，并使用对应版本的 USB loader。

### 3.3 串口

- 波特率：**1500000**
- 控制台：`ttyS2`
- 建议使用 **CP2104** 串口模块；CH340G/PL2303HX 在本板上常见只能读不能写。

```bash
miniterm /dev/ttyUSB0 1500000
```

## 4. 首次启动检查

基础镜像默认用户/密码为 `root` / `1234`，但首次成功启动会自动进入强制初始化流程，要求立即修改 root 密码并创建普通用户；不要沿用默认密码长期使用。

### 4.1 首次启动自动扩容根分区

镜像内置一次性服务 `tn3399-firstboot-resize.service`，在 `local-fs.target` 之后、`basic.target` 之前运行，调用 Armbian 的 `armbian-resize-filesystem` 把唯一 ext4 根分区扩展到整盘并在线 `resize2fs`。镜像组装脚本会删除 Armbian 原服务在 `basic.target.wants` 中的软链接，避免重复改分区表。

```bash
# 确认服务状态与结果
systemctl status tn3399-firstboot-resize.service || true
cat /var/lib/tn3399-firstboot-resize.done
tail -n 80 /var/log/tn3399-firstboot-resize.log
df -h /
lsblk
```

在 16GB eMMC 上，`/` 应从镜像的约 1.7 GiB 增长到约 15 GiB。若 `/var/run/resize2fs-reboot` 存在，说明分区表未能在线刷新，服务会保留并在重启后再执行一次。

如需禁用，可在 rootfs 放 `/root/.no_rootfs_resize` 后重新执行 `sudo make image`，或启动后执行 `systemctl disable --now tn3399-firstboot-resize.service`。

### 4.2 首次启动交互式初始化

扩容完成后，系统进入多用户模式，串口会出现 `tn3399-firstboot-setup` 的提示（脚本会临时接管 `ttyS2`，结束后自动恢复 getty）。**必须依次完成**：

1. 设置 root 新密码（强制，输入不回显）。
2. 创建普通用户、设置密码，并加入 `sudo` 组。
3. 选择 APT 镜像源：
   - 教育网/公网：清华 TUNA、中国科大 USTC、上海交大 SJTU；
   - 公网：阿里云、华为云；
   - 也可选 6 保留官方源。
   
   每个选项都会同时写入 Armbian 源、Debian 主源和 `trixie-security` 安全更新源，避免只换 Armbian 而漏掉安全更新。
4. 自动 `apt-mark hold` 已安装的 Armbian 内核包（`linux-image-current-rockchip64` / `linux-dtb-current-rockchip64`），防止 `apt upgrade` 覆盖本项目手工安装的 vendor 6.1 内核与模块。
5. 输入新主机名，脚本同步更新 `/etc/hostname` 和 `/etc/hosts`。

完成后检查：

```bash
cat /var/lib/tn3399-firstboot-setup.done
cat /etc/tn3399-mirror.choice
cat /etc/tn3399-kernel-lock
apt-mark showhold
hostname
tail -n 100 /var/log/tn3399-firstboot-setup.log
```

> 若中途按 Ctrl-C 或网络更新失败未完成全部步骤，脚本不会写完成标记，下次重启会重新进入初始化；密码不会被写入日志。按 Ctrl-C 后串口登录会自动恢复。

```bash
uname -a
cat /proc/device-tree/compatible
cat /etc/tn3399-v3-release

# MPP 驱动
ls -l /dev/mpp_service
ls -l /dev/dma_heap/ 2>/dev/null || true
dmesg | grep -iE 'mpp|rkvdec|vdpu|vepu'

# MPP 用户态库
ldconfig -p | grep rockchip_mpp
mpi_dec_test -h
mpi_enc_test -h

# 网络 / WiFi / 蓝牙
ip link
iw dev
rfkill list
hciconfig -a

# 音频
aplay -l
```

## 5. 常见问题

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 上电无任何串口输出 | 串口模块不兼容、波特率不对、U-Boot 未写入 | 换 CP2104；确认 1500000；检查镜像 32KiB 处是否有 U-Boot |
| 卡在 DDR 初始化 | DDR blob 与 K4B8G16 DDR3 时序不匹配 | 当前已用 `rk3399_ddr_800MHz_v1.30.bin`；可尝试 rkbin 中其他 800MHz blob 后重建 U-Boot |
| 内核 panic / 挂载根分区失败 | DTB 名不一致 | 核对 `armbianEnv.txt` 中 `fdtfile=rockchip/rk3399-tn3399-v3.dtb` |
| WiFi 不可用 | `bcmdhd` 未加载或固件路径错误 | `dmesg | grep -i bcmdhd`；检查 `/lib/firmware/brcm/fw_bcm43455c0_ag.bin` 与 `nvram_ap6255.txt` |
| 蓝牙不可用 | HCI UART 固件/协议未启用 | 检查 `CONFIG_BT_HCIUART_BCM=y` 与 `/lib/firmware/brcm/BCM4345C0.hcd` |
| `/dev/mpp_service` 不存在 | 用了主线 DTS 或主线内核 | 必须使用 BSP DTS（include `rk3399-linux.dtsi`）和 vendor 6.1 内核 |
| SATA 盘不识别 | JMS578 UAS 兼容问题 | 检查 `CONFIG_USB_UAS=y`；可在内核 cmdline 加 `usb_storage.quirks=152d:0578:u` 强制走 usb-storage |
| 无 HDMI 音频 | 声卡序号变化 | `aplay -l` 确认声卡，使用 `mpv --audio-device='alsa/default:CARD=...'` 指定 |
