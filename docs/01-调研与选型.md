## 2. 官方与社区支持现状

### 2.1 Rockchip 官方 BSP

- `rockchip-linux/kernel` 官方仓库有 `develop-6.1` 分支（BSP kernel source），这是最接近“官方 6.x vendor 分支”的来源。
- Armbian 维护的 `armbian/linux-rockchip` 把 Rockchip BSP 整理成多条 RKR 分支；截至本项目固定版本：`rk-6.1-rkr7.2`、`rk-6.12-rkr1.1`。本项目选择 **rk-6.1-rkr7.2**，因为 MPP 官方文档明确列出对 6.1 内核的支持，且该分支代码已验证包含完整 MPP 驱动树。

### 2.2 Armbian 现状

Armbian 官方 `rockchip64` 家族当前 `current`/`edge`/`bleedingedge` 分别对应主线 6.18 / 7.3 / 7.4，设备树来自 mainline，配置使用 Panfrost；官方主线 defconfig 中没有 `CONFIG_ROCKCHIP_MPP_SERVICE`。因此：

- 若目标是“最新主线 + Panfrost”，可直接用 retro98boy 的 Armbian fork（主线 6.18）。
- 若目标是“6.x vendor + MPP”，必须单独引入 vendor 内核。本项目采用后者。

### 2.3 lanseyujie/tn3399_v3 的价值与局限

该仓库是最早期的 TN3399_V3 折腾记录，提供了完整启动流程、rkbin、rootfs 打包、串口与刷机注意事项。关键做法：

- 把 `rk3399-rock960.dts` 复制为 `tn3399-linux.dts`/`dtb`；
- 在 DTS 中把 `bcm4329-fmac` 改成 `bcm43455-fmac`；
- 使用 Linaro 7.5 工具链、linux-5.8.y、u-boot 主线或 Rockchip stable-4.4；
- 串口建议使用 CP2104（CH340G/PL2303HX 只能读不能写）。

局限：它借用了 Rock960 的板级 compatible，不能准确表达本板的 PMIC/LED/音频/风扇/AP6255 细节，也不是 6.x vendor 路线。本项目保留它的刷机/串口经验，但不沿用它的 DTB 命名。

### 2.4 retro98boy 的适配

`retro98boy/tiannuo-tn3399-v3-linux` 与 `retro98boy/armbian-build` 提供了目前最完整的 TN3399_V3 适配：

- 板级配置 `tiannuo-tn3399-v3.csc`：`BOOT_FDT_FILE="rockchip/rk3399-tn3399-v3.dtb"`、`BOOT_SCENARIO="binman"`、U-Boot `v2026.01`；
- U-Boot defconfig `tn3399-v3-rk3399_defconfig` 与 DT/SDRAM 补丁；
- BSP 版和主线版 `rk3399-tn3399-v3.dts`；
- AP6255 的 BSP/mainline 两套固件；
- ALC5640 的 ALSA UCM 配置；
- 主线/BSP 内核两种构建说明。

本项目直接复用其 BSP DTS、U-Boot 补丁、固件与 UCM，并补充 vendor 6.1 内核与 MPP 用户态库。

## 3. 为什么 DTB 名必须固定为 rk3399-tn3399-v3.dtb

内核启动时会把 U-Boot 传入的 DTB 与 `compatible` 匹配驱动。若继续用 `tn3399-linux.dtb` 或 `rk3399-rock960.dtb`：

- `compatible` 会变成 `rockchip,rk3399-rock960`，板级差异（PMIC 中断、RTC、LED、风扇、WL/BT GPIO、音频路由）可能丢失或错配；
- U-Boot 的 `CONFIG_DEFAULT_FDT_FILE`、Armbian 的 `fdtfile`、rootfs 中的 DTB 路径三者一旦不一致，会出现根分区挂载失败或控制台无输出。

本项目统一为：

```text
compatible = "tiannuo,tn3399-v3", "rockchip,rk3399"
DTB = rockchip/rk3399-tn3399-v3.dtb
console = ttyS2,1500000
```

## 4. MPP 可用性证据

在 `armbian/linux-rockchip@rk-6.1-rkr7.2` 中确认存在：

- `drivers/video/rockchip/mpp/mpp_service.c`
- `mpp_rkvdec.c` / `mpp_rkvenc.c` / `mpp_vdpu1.c` / `mpp_vdpu2.c` / `mpp_vepu1.c` / `mpp_vepu2.c`
- `arch/arm64/boot/dts/rockchip/rk3399-linux.dtsi` 中的 `&mpp_srv { status = "okay"; }`、`&rkvdec`、`&vdpu`、`&vepu`
- `drivers/dma-buf/heaps/rk_system_heap.c`、`rk_cma_heap.c`、`drivers/dma-buf/rk_heaps/`
- `rockchip_linux_defconfig` 中的 `CONFIG_ROCKCHIP_MPP_SERVICE=y` 等一整套开关

因此选择 BSP DTS（include `rk3399-linux.dtsi`）而不是主线 DTS，是让 MPP 一次到位的关键。

## 5. 备选方案

| 方案 | 优点 | 缺点 | 本项目态度 |
|---|---|---|---|
| retro98boy Armbian fork（主线 6.18） | 构建链最顺、Panfrost 开源图形栈、ALSA/AP6255 已适配 | 无 vendor MPP service，硬解走 mainline V4L2/Hantro，API 不同 | 作为备选主线分支，DTS 已随项目提供 |
| ophub/amlogic-s9xxx-armbian 的 rk3399 6.1.y 镜像 | 现成镜像、刷机工具完善 | 板级 DTB 与 TN3399_V3 细节可能不一致，依赖其私有包体系 | 不作为基线 |
| 纯主线 5.8/6.x + lanseyujie DTS | 资料最多 | DTB 身份错误、MPP 不完整、内核较老 | 不采用 |
| 本项目：Armbian rootfs + vendor 6.1 + U-Boot 2026.01 | 兼顾 Armbian 生态、6.1 vendor 驱动和 MPP | 需要自己组装镜像，不能直接用官方 compile.sh 一键出图 | 采用 |
