# 05 内核版本跟踪与更新

本项目刻意把"版本来源"与"构建逻辑"分离：所有上游版本都集中在 `config/project.env`，构建脚本只读取变量。这样跟踪和升级新版本只需改配置 + 少量兼容性检查，不必改脚本。

## 1. 版本集中管理的位置

`config/project.env` 中与版本相关的关键变量：

| 变量 | 含义 | 当前值 |
|---|---|---|
| `KERNEL_REPO` / `KERNEL_REF` / `KERNEL_COMMIT` | vendor 内核仓库 / 分支 / 固定提交 | `armbian/linux-rockchip` / `rk-6.1-rkr7.2` / `02b126b9…` |
| `UBOOT_REF` / `UBOOT_COMMIT` | U-Boot 标签 / 固定提交 | `v2026.01` / `127a42c7…` |
| `RKBIN_COMMIT` | DDR/BL31 二进制仓库提交 | `3e288fe8…` |
| `MPP_REF` / `MPP_COMMIT` | MPP 分支 / 固定提交 | `develop` / `9b56348c…` |
| `DDR_BLOB` / `BL31_BLOB` | rkbin 内 DDR 与 BL31 的相对路径 | `bin/rk33/rk3399_ddr_800MHz_v1.30.bin` / `…bl31_v1.36.elf` |
| `ARMBIAN_BASE_URL` / `ARMBIAN_BASE_SHA` | rootfs 基础镜像 URL 与校验 | Armbian 26.8.1 trixie minimal |

> **固定 commit 而非浮动分支**是刻意设计：分支会前进，固定提交保证镜像可复现。升级时显式改 commit。

## 2. 如何跟踪 vendor 6.1 内核的新版本

### 2.1 上游分支命名规律

Armbian 维护的 Rockchip vendor 内核仓库 `https://github.com/armbian/linux-rockchip` 分支按 `rk-<内核版本>-rkr<版本>` 命名，例如：

```
rk-5.10-rkr4 / rkr5.1 / rkr6 / rkr8
rk-6.1-rkr1 / rkr3 / rkr4.1 / rkr5 / rkr5.1 / rkr6.1 / rkr7.2
rk-6.12-rkr1 / rkr1.1
```

- `rk-6.1-rkr7.2` 中的 `rkr7.2` 是 Rockchip BSP 的 RKR 发布号，**数字越大越新**。
- 本项目选择 6.1 系列，因为 Rockchip MPP 官方文档明确支持 6.1，且该分支 `drivers/video/rockchip/mpp` 完整。

### 2.2 列出可用分支（国内网络走代理）

```bash
git -c http.version=HTTP/1.1 ls-remote --heads \
  https://gh-proxy.com/https://github.com/armbian/linux-rockchip.git \
  | sed 's#refs/heads/##' | awk '{print $2}' | grep '^rk-6\.1-' | sort -V
```

### 2.3 确定新分支的固定提交

```bash
git -c http.version=HTTP/1.1 ls-remote \
  https://gh-proxy.com/https://github.com/armbian/linux-rockchip.git \
  refs/heads/rk-6.1-rkr<新版本>
# 输出形如：<commit>  refs/heads/rk-6.1-rkrX.Y
```

把该 commit 记入 `KERNEL_COMMIT`，分支名记入 `KERNEL_REF`。

### 2.4 官方 BSP 的对应关系

Rockchip 官方 BSP 在 `https://github.com/rockchip-linux/kernel` 的 `develop-6.1` 分支。Armbian 的 `rk-6.1-rkr*` 是对官方 BSP 的重新整理与补丁集。若需确认某个 RKR 版本对应哪个官方 BSP 提交，可对比两边 `Makefile` 顶部的 `VERSION/PATCHLEVEL/SUBLEVEL` 与 `drivers/video/rockchip/mpp` 是否存在。

## 3. 升级内核版本的完整步骤

1. **改配置**：编辑 `config/project.env` 的 `KERNEL_REF` 与 `KERNEL_COMMIT`（必要时同步 `RKBIN_COMMIT`、`DDR_BLOB`、`BL31_BLOB`）。
2. **重新拉取**：`make fetch`。`fetch_repo` 按 commit 缓存 tarball（位于 `sources/.tarballs/`），新 commit 会触发重新下载与解压。
3. **检查 DTS 兼容性**（最常见破坏点，见第 4 节）：确认 `config/kernel/rk3399-tn3399-v3.dts` 中引用的所有 `&label` 在新内核 dtsi 中都存在；确认内核 `arch/arm64/boot/dts/rockchip/Makefile` 里 DTB 目标前缀（`dtb-` 还是 `dt-`）。构建脚本 `build-kernel.sh` 已自动探测前缀。
4. **检查 defconfig 符号**：新内核可能增删 Kconfig 符号。`config/kernel/tn3399-v3.config` 中若某符号在新内核不存在，`make olddefconfig` 会静默丢弃它。升级后检查 `sources/linux-rockchip/.config`，确认 `CONFIG_ROCKCHIP_MPP_OSAL=y`、`CONFIG_BCMDHD`、`CONFIG_REALTEK_PHY` 等关键项仍在。
5. **重建**：`make uboot && make kernel && make mpp && sudo make image`（若 rkbin 也升级，必须重做 U-Boot；若仅内核升级，U-Boot 可复用）。
6. **校验**：`make verify` 与 `bash scripts/verify-artifacts.sh` 全部 `[OK]`。
7. **真机验证**：按 `docs/03-验证清单.md` 在 TN3399_V3 板子上确认 DDR、串口、WiFi、HDMI、SATA、MPP 硬解。

## 4. 升级时重点检查的 DTS 兼容性

历史上本项目踩过两个与新/旧内核 dtsi 不匹配相关的坑，升级时务必复查：

| 问题 | 现象 | 处理 |
|---|---|---|
| `&hdmi_hdcp2` 标签不存在 | `dtc` 报 `Label or path hdmi_hdcp2 not found`，DTB 不生成 | 该节点仅存在于较新内核；vendor 6.1 无此标签，已从本板 DTS 移除（HDMI 主功能由 `&hdmi`/`&display_subsystem` 提供） |
| DTB Makefile 前缀错误 | make 不报错但 DTB 从未编译，`output/kernel/*.dtb` 缺失 | 主线用 `dt-`，vendor BSP 用 `dtb-`；`build-kernel.sh` 已自动探测，升级后仍建议确认 `grep -n tn3399 sources/linux-rockchip/arch/arm64/boot/dts/rockchip/Makefile` |

## 5. 升级 MPP 用户态库

`rockchip-linux/mpp` 的 `develop` 分支持续更新，本项目固定 commit `9b56348c…`。升级步骤：

```bash
# 1. 查最新 commit（走代理）
git -c http.version=HTTP/1.1 ls-remote \
  https://gh-proxy.com/https://github.com/rockchip-linux/mpp.git refs/heads/develop

# 2. 改 config/project.env 的 MPP_COMMIT

# 3. 重新拉取与编译
make fetch && make mpp
```

注意 MPP 用户态库版本需与内核 MPP 驱动版本匹配；若升级内核后 `mpi_dec_test` 报 ioctl 不兼容，优先对齐两者版本。

## 6. 升级 rkbin / DDR blob

- DDR blob 路径在 `config/project.env` 的 `DDR_BLOB`，相对 `sources/rkbin/`。
- 本板 K4B8G16 DDR3 使用 800MHz 系列（当前 v1.30）；换版本时确保 rkbin commit 中确有该文件（`ls sources/rkbin/bin/rk33/rk3399_ddr_800MHz_*.bin`）。
- 升级 rkbin 或 DDR blob 后**必须重建 U-Boot**（`make uboot`），因为 TPL 会把 DDR blob 打包进 `idbloader.img`。
- USB loader（`USB_LOADER`，如 `rk3399_loader_v1.30.130.bin`）需与 DDR blob 版本配套，从 retro98boy 仓库或 rkbin tools 获取。

## 7. 变更记录建议

每次升级建议在提交信息中记录：新版本号与 commit、变更原因、受影响的组件、真机验证结果。可在仓库根目录维护 `CHANGELOG.md`（本项目未预置，按需创建）。
