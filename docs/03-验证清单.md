# 03 验证清单

## 1. 构建前静态校验

执行 `make verify` 做配置静态校验；构建完成后用 `STRICT=1 make verify` 要求所有产物必须存在。预期结果：

| 检查项 | 命令/条件 | 通过标准 |
|---|---|---|
| 板级 DTS 存在 | `test -f config/kernel/rk3399-tn3399-v3.dts` | 文件存在 |
| DTB compatible | `grep 'compatible = "tiannuo,tn3399-v3", "rockchip,rk3399"'` | 命中 |
| BSP DTS 引入 MPP | `grep '#include "rk3399-linux.dtsi"'` | 命中 |
| U-Boot 默认 DTB | `grep 'CONFIG_DEFAULT_DEVICE_TREE="rockchip/rk3399-tn3399-v3"'` | 命中 |
| 串口波特率 | `grep 'CONFIG_BAUDRATE=1500000'` | 命中 |
| MPP 内核配置 | `grep '^CONFIG_ROCKCHIP_MPP_SERVICE=y'` | 命中 |
| AP6255 驱动 | `grep '^CONFIG_BCMDHD=m'` | 命中 |
| RTL8211E PHY | `grep '^CONFIG_REALTEK_PHY=y'` | 命中 |
| 首次启动扩容脚本 | `test -x config/rootfs/tn3399-firstboot-resize` | 文件存在且可执行 |
| 扩容 service | `test -f config/rootfs/tn3399-firstboot-resize.service` | 文件存在 |
| 复用 Armbian 扩容实现 | `grep armbian-resize-filesystem config/rootfs/tn3399-firstboot-resize` | 命中 |

## 3. 刷机后运行时校验

| 项目 | 命令 | 预期输出/判据 |
|---|---|---|
| 内核版本 | `uname -r` | 6.1.x，版本写入 `/etc/tn3399-v3-release` |
| 板级 compatible | `cat /proc/device-tree/compatible` | 含 `tiannuo,tn3399-v3` |
| DTB 路径 | `cat /boot/armbianEnv.txt | grep fdtfile` | `rockchip/rk3399-tn3399-v3.dtb` |
| 串口 | `dmesg | grep ttyS2` | 1500000 8N1 |
| eMMC | `lsblk` / `dmesg | grep mmc` | `mmcblk2` 被识别，HS400 正常 |
| 千兆网 | `ethtool eth0` | Speed 1000Mb/s，Full Duplex |
| WiFi | `ip link show wlan0` / `iw dev` | wlan0 存在，可扫描 |
| 蓝牙 | `hciconfig -a` | hci0 UP，可 `bluetoothctl scan on` |
| SATA | `lsblk` | JMS578 下的 SATA 盘出现为 `/dev/sdX` |
| HDMI | `modetest -M rockchip` | 有 HDMI 连接器与模式 |
| GPU | `ls /dev/mali*` 或 `glxinfo -B` | Mali 设备节点存在（vendor 驱动） |
| 音频 | `aplay -l` | `tn3399-v3`(ALC5640) 与 `hdmi-sound` |
| MPP 驱动 | `ls -l /dev/mpp_service` | 设备节点存在 |
| MPP dma-heap | `ls /dev/dma_heap/` 或 `dmesg | grep rk_system_heap` | Rockchip heap 可用 |
| MPP 用户态 | `mpi_dec_test -h` | 输出帮助信息 |
| 首次启动扩容服务 | `systemctl status tn3399-firstboot-resize.service` | 首次启动后为 inactive(dead)/enabled→disabled，日志无报错 |
| 扩容完成标记 | `cat /var/lib/tn3399-firstboot-resize.done` | 含 `done` 与扩容后的 `size=` |
| 根分区容量 | `df -h /` / `lsblk` | 16GB eMMC 上 `/` 约 15 GiB，分区表为整盘 |
| 扩容日志 | `tail -n 80 /var/log/tn3399-firstboot-resize.log` | 包含 Armbian 扩容输出，无 `Fail to find the target partition` |
| 首启初始化服务 | `systemctl status tn3399-firstboot-setup.service` | 完成后 inactive(dead)，日志无报错；串口 getty 已恢复 |
| 初始化完成标记 | `cat /var/lib/tn3399-firstboot-setup.done` | 含 `done`、`user=`、`hostname=`、`mirror=`、`held_kernel=` |
| root 密码 | `passwd -S root` | 状态 `P`，且已不是默认 `1234`（人工确认） |
| 普通用户 sudo | `id <用户名>` / `sudo -l -U <用户名>` | 含 `sudo` 组，具备 sudo 权限 |
| APT 镜像 | `cat /etc/tn3399-mirror.choice`；`cat /etc/apt/sources.list.d/*.sources` | 记录所选镜像；含 Armbian、Debian 主源与 `trixie-security` 安全源 |
| 内核锁定 | `apt-mark showhold` | 含 `linux-image-current-rockchip64`、`linux-dtb-current-rockchip64` |
| 主机名 | `hostnamectl` / `cat /etc/hosts` | 新主机名，`127.0.1.1` 已同步 |
| 硬解实测 | `ffmpeg -hwaccel rkmpp -i sample.mp4 -f null -` | 无 `mpp_service` 报错；进度正常 |

> 若 `ffmpeg` 未带 `rkmpp` 支持，可先用 MPP 自带 `test/mpi_dec_test` 验证；ffmpeg-rkmpp 需要单独打补丁编译，不属于本项目最小交付范围。

## 4. 失败回退路径

| 场景 | 回退方式 |
|---|---|
| vendor 6.1 无法启动 | 使用随项目提供的 `rk3399-tn3399-v3-mainline.dts`，改用 retro98boy Armbian fork 的 `current`（主线 6.18）构建 |
| DDR 初始化失败 | 当前用 `rk3399_ddr_800MHz_v1.30.bin`；可换 rkbin 中其他 800MHz blob 与对应 loader |
| AP6255 bcmdhd 不工作 | 改用 mainline `brcmfmac`：在内核 config 中打开 `CONFIG_BRCMFMAC_SDIO`，DTS 换主线版，并放置 `brcmfmac43455-sdio.*` 固件 |
| MPP 用户态分配失败 | 确认 `/dev/dma_heap/system*` 权限；老版本 MPP 对早期 6.1 dma-heap 不完善，更新到本项目固定 commit |
