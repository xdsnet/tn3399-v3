# 06 在 KVM 虚拟机内构建（脱敏 / 参数化）

本项目提供一套**可选的**"虚拟机内构建"编译模式：把重负载的解压与交叉编译放到一台 KVM 虚拟机里完成，宿主机只负责同步源文件、触发构建、回拷产物。这样做的价值是：

- 构建过程可快照、可回滚，不污染宿主机环境；
- 规避某些容器/受限环境对大量文件创建 syscall 的节流（实测本机会话约 38 ms/次，而 VM 内约 0.05 ms/次）；
- 便于在多台机器间复用同一套构建流程。

> **脱敏设计**：仓库中**不含任何真实 IP、用户名、SSH 密钥路径或虚拟机名**。这些环境相关信息全部放在 `config/vm.env`，该文件已被 `.gitignore` 排除，不会提交。仓库里只有不含真实值的 `config/vm.env.example` 模板。

## 1. 两种连接方式

| 方式 | `VM_CONNECT` | 凭据需求 | 适用 |
|---|---|---|---|
| guest-agent（推荐） | `guest-agent` | 无（通过 libvirt `qemu-agent-command`） | VM 已安装 qemu-guest-agent；零密钥、最安全 |
| SSH | `ssh` | SSH 密钥（路径来自配置） | 需要在 VM 与宿主机间传输大文件（如 1.7 GiB 镜像）时更高效 |

## 2. 首次配置

```bash
cd /datas/codes/tn3399
cp config/vm.env.example config/vm.env
$EDITOR config/vm.env        # 填写你的 VM 名 / 连接信息 / VM 内项目目录
```

guest-agent 模式的最小配置：

```bash
VM_CONNECT=guest-agent
VM_LIBVIRT_URI=qemu:///system
VM_NAME=你的虚拟机名
VM_PROJECT_DIR=/home/你的用户/tn3399
```

SSH 模式额外填写 `VM_SSH_TARGET`、`VM_SSH_PORT`、`VM_SSH_KEY`（可留空用默认密钥）。

> `config/vm.env` 是本地文件；即使填写了真实 IP 或密钥路径，也不会进入 git。

## 3. 使用流程

```bash
make vm-check                       # 1. 检查连接与配置（打印的配置已脱敏）
make vm-sync                        # 2. 同步 Makefile/config/scripts/docs 到 VM
make vm-run TARGET=kernel           # 3a. 在 VM 内执行指定 make 目标
make vm-run TARGET="kernel mpp"     #     可一次执行多个目标
make vm-pull                        # 4. 回拷 VM 的 output/ 到宿主机
```

一键完成（sync → `make all` → pull）：

```bash
make vm-all
```

## 4. 在 VM 内需要预装的依赖

与宿主机构建相同（见 `docs/02-构建与刷机.md` 第 1 节），特别注意 U-Boot binman 需要：

```bash
sudo apt install -y build-essential bison flex libssl-dev libncurses-dev bc \
  device-tree-compiler cmake gcc-aarch64-linux-gnu g++-aarch64-linux-gnu \
  swig python3-dev python3-setuptools python3-pyelftools libgnutls28-dev aria2
```

guest-agent 模式还需在 VM 内安装并启动 `qemu-guest-agent`。

## 5. 传输通道说明

- **guest-agent 模式**：`vm-exec.py` 通过 `virsh qemu-agent-command` 执行命令；小文件用 base64 传输。适合源码与脚本同步。**超大镜像（>1 GiB）建议改用 SSH 模式回拷**，base64 通道效率低。
- **SSH 模式**：用 `scp` 传输文件，支持大镜像高效回拷。密钥路径仅从 `config/vm.env` 读取，脚本不打印密钥内容。

## 6. 与"验证用虚拟机"的区别

`docs/04-KVM验证方案.md` 描述的虚拟机用途是**验证构建成果**（DTB 反编译、rootfs 用户态冒烟），不能启动 RK3399 内核。本文件描述的**构建用虚拟机**用途是**执行交叉编译**（`make uboot/kernel/mpp/image`）。两者可以是同一台 VM，也可以分开。

## 7. 安全边界

- 脚本只读取 `config/vm.env` 中的连接参数，不将其写入日志或输出。
- 不上传任何 SSH 私钥到 VM 或外部网络；SSH 模式仅在宿主机本地用私钥发起连接。
- 构建产物、下载源码、镜像均通过 `.gitignore` 排除，不会因本流程误入 git。
